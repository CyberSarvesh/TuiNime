# Publishing tuinime

How a release gets from a git tag to `winget install`, `scoop install`, `brew install`,
the AUR and crates.io. The first release takes some one-time setup. After that, a release is
mostly a version bump and a tag.

## One-time setup

1. **Push the repo** to `github.com/CyberSarvesh/TuiNime` (public).
2. **Homebrew tap.** Create an empty public repo `CyberSarvesh/homebrew-tap`.
   Make a fine-grained GitHub token with *Contents: read and write* on that repo only, and add it
   to TuiNime's *Settings → Secrets and variables → Actions* as `HOMEBREW_TAP_TOKEN`.
   Without it, the release's Homebrew step fails.
3. **Scoop bucket.** Create a public repo from the template
   [ScoopInstaller/BucketTemplate](https://github.com/ScoopInstaller/BucketTemplate) named
   `scoop-bucket`. Its built-in "Excavator" workflow checks for new releases every few hours and
   updates the manifest for you.
4. **crates.io.** Log in at [crates.io](https://crates.io) with GitHub, create an API token, and run
   `cargo login` once.
5. **AUR.** Make an account at [aur.archlinux.org](https://aur.archlinux.org) and add your SSH key.
6. **winget token.** A classic GitHub token with the `public_repo` scope, saved as the `WINGET_TOKEN`
   secret. winget-releaser uses it to open pull requests from your fork of `winget-pkgs`.
   Fork [microsoft/winget-pkgs](https://github.com/microsoft/winget-pkgs) first.

## Every release

1. Bump `version` in `Cargo.toml` (for example to `0.2.0`), run `cargo build` so `Cargo.lock`
   updates, and commit.
2. Check that the release would build:

   ```bash
   dist plan
   ```

3. Tag and push:

   ```bash
   git tag v0.2.0
   git push origin main v0.2.0
   ```

   GitHub Actions (`.github/workflows/release.yml`) then builds Windows, Linux and macOS
   (x86_64 + arm64), creates the GitHub Release with the archives, checksums and the
   `tuinime-installer.sh` / `.ps1` one-liners, and pushes the Homebrew formula to the tap.
   For later versions, `.github/workflows/winget.yml` also submits the update to winget.
4. **crates.io:** `cargo publish` (try `cargo publish --dry-run` first). `cargo binstall tuinime`
   finds the GitHub Release binaries on its own.
5. **Scoop:** Excavator picks the release up by itself. To do it now, run the bucket's
   `bin/checkver.ps1 tuinime -u` and commit the result.
6. **AUR:** in your clone of `ssh://aur@aur.archlinux.org/tuinime-bin.git`, copy in
   `packaging/aur/PKGBUILD`, set `pkgver`, then:

   ```bash
   updpkgsums
   makepkg --printsrcinfo > .SRCINFO
   git commit -am "v0.2.0" && git push
   ```

## The first time for each store

### Scoop bucket

Copy `packaging/scoop/tuinime.json` into the bucket's `bucket/` folder. Replace
`REPLACE_AFTER_FIRST_RELEASE` with the hash from the release's
`tuinime-x86_64-pc-windows-msvc.zip.sha256`, or run `bin/checkver.ps1 tuinime -u`, which fills it
in. Commit, then check that it installs:

```powershell
scoop bucket add tuinime https://github.com/CyberSarvesh/scoop-bucket
scoop install tuinime
```

### winget (manual the first time)

The winget workflow can only update a package that is already in winget, so the first version is
submitted by hand. Use Microsoft's tool, which downloads the zip, computes the hash and asks a few
questions:

```powershell
winget install wingetcreate
wingetcreate new https://github.com/CyberSarvesh/TuiNime/releases/download/v0.1.0/tuinime-x86_64-pc-windows-msvc.zip
```

Answers to use:

- Package identifier: `CyberSarvesh.TuiNime`
- Installer type: `zip`, nested installer type `portable`, nested file `tuinime.exe`, command alias `tuinime`
- License: `MIT`
- Dependency: `shinchiro.mpv` (winget's mpv package)

Let it submit the pull request. Automated checks run first, then a Microsoft moderator reviews it,
usually within a few days. Once it is merged, later releases go through
`.github/workflows/winget.yml` without you.

### Official Scoop Extras / homebrew-core

These are optional, once the project has users. Both expect some popularity (stars, forks,
downloads). Their maintainers decide what they accept, and they may decline an app that streams
from unofficial sites. Your own bucket and tap don't depend on anyone's approval.

## Files

| File | Used by |
|---|---|
| `dist-workspace.toml`, `[profile.dist]` in `Cargo.toml` | dist: build targets, installers, Homebrew tap |
| `.github/workflows/release.yml` | generated by `dist generate`; regenerate it after changing `dist-workspace.toml` rather than editing it by hand |
| `.github/workflows/winget.yml` | winget updates after the first version |
| `packaging/scoop/tuinime.json` | source copy of the Scoop manifest |
| `packaging/aur/PKGBUILD` | source copy of the AUR package |
